# 排障道场 · 产线排障情景训练

给装配线新技术员的排障训练：同一个报警，每一局背后的原因随机；学员要在工位图上自己决定查什么、在怀疑板上写下怀疑再一一排除，修完不验证会出后续事故，结束后和老师傅的排查路径并排对比。

**在线体验：**
- v2（现在的版本）：https://zeroonehub.github.io/line-troubleshoot-trainer/
- v1（第一版，试玩反馈“像做题”）：https://zeroonehub.github.io/line-troubleshoot-trainer/v1.html

> 这是演示版。场景、设备和数值都是示例；页面里角色的对话是预先写好的规则，不调用真实模型。

---

## 为什么要做

新人和老师傅差的不是手艺，是排障思路：先看什么、怀疑什么、查什么能排除什么、修完怎么验证。可真实故障发生得少、停线代价高，没法拿真设备反复练，新人只能在故障发生时跟着老师傅边看边学。

这个训练要练的是一件事：**遇到报警，自己想得到要查什么，并且用证据排除。**

## 怎么体验（每局 5–10 分钟）

场景：夜班两点，3 号拧紧工位报“扭矩低于下限”，操作工说“刚换了一箱螺栓”。

1. 先看 HMI 上的拧紧曲线，框出异常段，判断是打滑、滑牙还是提前停止；
2. 在怀疑板上写下你怀疑的原因；
3. 在工位图上点部件做检查，每项检查都要花时间；套筒是运动部件，不上锁就碰，直接失败；
4. 选择修复措施，再自己决定要不要做首件确认、要不要追溯；
5. 看复盘：你的路径和老师傅的路径并排，每次检查排除了什么、哪些是白查。

同一个报警背后有 3 种根因：**套筒磨损、螺栓批次异常、程序选错**，每局随机抽一种。想指定根因，在网址后面加：

| 根因 | 网址 |
|---|---|
| 套筒磨损 | `.../line-troubleshoot-trainer/#socket` |
| 螺栓批次异常 | `.../line-troubleshoot-trainer/#bolt` |
| 程序选错 | `.../line-troubleshoot-trainer/#program` |

> 建议先玩 `#program`：修好以后如果不追溯，下工序会发现 12 件扭矩不足。**后果比扣分记得牢。**

## 从 v1 到 v2：为什么推倒重做

**v1** 是一个固定关卡：底部 9 个处理动作按钮，学员按顺序点；根因永远是套筒磨损；每一步老师傅点评一句；求助扣星，按用时评星。

试玩的反馈是“**像做题**”：第二局照着点一分多钟就过了。拆下来有五个原因：

| v1 的问题 | 为什么 |
|---|---|
| 动作清单本身就是答案提示 | “检查套筒”这个按钮就在提醒你 |
| 根因固定 | 玩一次就背下来了 |
| 每一步都说“对” | 学员不用自己判断 |
| 没有取舍 | 不验证也不会出事 |
| 看曲线只是读一段文字 | 没练到读曲线 |

根子不在玩法，在**学习目标写成了“知道每种报警的正确排查步骤”**。按“知道”去设计，做出来的自然是记步骤的东西；老师傅真正的本事是“想得到”。所以先把学习目标改成“自己想到要查什么”，再重做 v2：

| 机制 | 对应的学习目标 |
|---|---|
| 同一报警随机根因 | 不被干扰线索带偏，背答案没用 |
| 工位图上自己点部件，不列动作清单 | 自己想到要查什么 |
| 怀疑板 | 先提出怀疑，再用检查去排除 |
| 检查要花时间 | 先查最能区分原因的那一项 |
| 读拧紧曲线 | 第一步先看数据，不是先复位、换件 |
| 过程中不判对错，修完不验证有延迟后果 | 修完一定验证、该追溯就追溯 |
| 安全红线（不上锁碰运动部件直接失败） | 安全动作零容忍 |
| 复盘对比老师傅路径 | 知道老师傅为什么这么查 |

v2 里有 9 个部件、15 项检查、5 种修复措施和 5 个候选怀疑。星级从 3 星往下扣，达标线是“老师傅参考用时 × 1.5 + 2 分钟”，同时看检查效率。

## AI 放在哪里

**AI 只管“怎么说”，不管“对不对”。**

- 正式方案里，大模型扮演操作工、值班工程师等角色，回答学员的问话，并把学员写的怀疑对应到具体原因；
- 它**拿不到这一局的根因，也拿不到检查矩阵**，只拿到这种情况下操作工会怎么说，所以说不出答案；
- 输出再过一遍规则检查：有没有根因的名字、有没有证词里没有的部件、数字和时间、有没有评价对错的话，不通过就换成固定证词；
- 根因、检查结果、评分和后果，全部由老师傅审核过的根因卡和检查矩阵决定；安全规程用固定文本，AI 不改写；
- AI 不可用时，降级成固定证词，练习照常进行。

演示版里的对话都是预先写好的规则，用来展示交互，没有接模型。

## 内容从哪里来

内容的单位是**根因卡**：一个报警背后的一种原因，写清楚曲线什么样、操作工怎么说、每一项检查在这种原因下会看到什么、怎么修、怎么验证、修错了会怎样、老师傅怎么想。出题流程是：

```
老师傅口述（约 10 分钟）→ 按追问提纲补问“怎么排除其他原因”“修错了会怎样”
→ AI 按模板起草根因卡和检查矩阵 → 规则自动查矛盾、查区分度
→ 老师傅逐格确认 → 安全内容 EHS 审核 → 上线
```
